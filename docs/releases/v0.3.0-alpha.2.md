# DevSift v0.3.0-alpha.2

> Release-candidate notes: no `v0.3.0-alpha.2` tag, release, or public asset
> exists yet. These exact notes become the release body only after every live
> signing and publication gate succeeds.

This candidate is intended to supersede the failed, immutable
`v0.3.0-alpha.1` source tag. If published, it will ship the first signed and
notarized DevSift macOS app together with the read-only command-line archive.

## Included

- `DevSift.app`, Developer ID signed, Apple notarized, and stapled;
- universal `arm64` and `x86_64` executables with a macOS 14 deployment floor;
- English and Korean native-app interfaces with a persisted language choice;
- explicit scan, policy review, and dry-run selection;
- on macOS 26 or newer, narrowly scoped npm `_cacache` quarantine, receipt-bound
  restore, and separately confirmed permanent deletion or deletion retry;
- the read-only `devsift` CLI with `status`, `scan`, and `classify` commands;
- separate SHA-256 checksum files and GitHub provenance for both archives.

The CLI and public DevSiftCore API remain read-only. App mutation is manual,
single-item, npm-only, and available only through package-scoped Core workflows.

## Install and launch the app

After publication, download `DevSift-0.3.0-alpha.2-macos-universal.zip` and its
matching `.sha256` file from the release, then run:

```shell
shasum -a 256 -c DevSift-0.3.0-alpha.2-macos-universal.zip.sha256
ditto -x -k DevSift-0.3.0-alpha.2-macos-universal.zip .
open DevSift.app
```

You can move `DevSift.app` to `/Applications` before opening it. Do not disable
Gatekeeper. The stapled ticket permits offline notarization verification.

The app starts empty and never scans, restores, or deletes anything on launch.
Choose a folder explicitly. Use the globe menu to select `System`, `English`,
or `Korean` without resetting the active window workflow.

## Verify publisher and provenance

After extracting the app:

```shell
codesign --verify --all-architectures --strict --verbose=2 DevSift.app
xcrun stapler validate -v DevSift.app
spctl --assess --type execute --verbose=4 DevSift.app
gh attestation verify \
  DevSift-0.3.0-alpha.2-macos-universal.zip \
  --repo jxewonkim/devsift \
  --signer-workflow jxewonkim/devsift/.github/workflows/release-app.yml \
  --source-ref refs/tags/v0.3.0-alpha.2 \
  --deny-self-hosted-runners
```

For the CLI archive:

```shell
shasum -a 256 -c SHA256SUMS
gh attestation verify \
  devsift-0.3.0-alpha.2-macos-universal.tar.gz \
  --repo jxewonkim/devsift \
  --signer-workflow jxewonkim/devsift/.github/workflows/release.yml \
  --source-ref refs/tags/v0.3.0-alpha.2 \
  --deny-self-hosted-runners
```

Checksums detect corruption or a mismatched download. The Developer ID
signature identifies the publisher. Notarization records Apple's acceptance of
the submitted bytes after automated checks; it is not an endorsement or a
complete security audit. GitHub attestation binds each archive to its tag
workflow and source ref.

## Permanent-deletion boundary

Quarantine is a recoverable same-volume rename and frees exactly 0 B. Permanent
deletion is a separate receipt-bound action requiring four independent risk
acknowledgements and an exact Core statement. It removes directory entries from
one selected quarantined tree; it is not secure erase. APFS snapshots, clones,
compression, concurrent filesystem activity, and delayed accounting mean the
reported capacity change may be zero or unavailable and is never a guaranteed
causal savings value.

## Known limitations

- DevSift is pre-alpha; review every path and disclosure before acting.
- Mutation requires macOS 26 or newer and fails before mutation on older
  systems. Read-only scanning and review support macOS 14 or newer.
- There is no background, scheduled, batch, arbitrary-path, active-cache, or
  launch-time cleanup.
- There is no privileged helper, telemetry, account, network dependency,
  installer package, Homebrew formula, or automatic updater.
- The app carries no sandbox or hardened-runtime exception entitlement. It runs
  with the same ordinary-user filesystem authority as a direct local build.
